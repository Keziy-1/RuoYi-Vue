## 1. 项目概述

RuoYi-Vue 是基于 SpringBoot + Vue3 + Element Plus 的前后端分离后台管理系统，本次迭代覆盖系统管理六大核心模块：登录认证、用户管理、角色管理、菜单管理、部门管理、系统日志。迭代目标为完成核心 RBAC 权限体系及日志审计能力的功能交付，为后续业务模块迭代提供稳定的基础框架支撑。

本轮测试作为第一轮功能迭代的质量门禁，按「P0 主流程必保、P1 场景全覆盖、P2 边界及异常补全」的策略执行，同步完成接口基础冒烟、登录页性能基准采样、核心流程自动化脚本搭建工作。

### 5.3 严重程度分布

- **严重级（3 条，已修复 3 / 已关闭 2）**：
  1. 角色管理-分配权限：菜单树父子不联动，影响授权效率与权限准确性；
  2. 登录认证-密码锁定：账户锁定机制失效，存在暴力破解风险；
  3. 部门管理-删除部门：级联删除导致用户 dept_id 置空，存在数据完整性风险。
  三条严重级缺陷均在本轮迭代修复并完成回归，无遗留严重问题。

- **一般级（6 条，已解决 3 / 新建 3）**：涉及手机号校验、用户状态刷新、角色重名校验、日志跨月查询、用户导入邮箱字段、角色数据权限刷新。3 条已解决待回归，3 条新建列入下一轮修复计划。

- **轻微级（3 条，已解决 2 / 新建 1）**：菜单图标显示、排序负数、登录日志类型显示。均为 UI 展示类问题，不影响主流程。

### 5.4 典型缺陷说明

**典型缺陷 1：部门管理-删除部门存在下级子部门未拦截删除（严重）**

| 项 | 内容 |
|---|---|
| 缺陷 ID | BUG-006 |
| 触发场景 | 部门管理中直接删除含多层子部门的顶级部门「若依科技」 |
| 根因分析 | 后端 SysDeptServiceImpl.deleteDeptById 未先调用 hasChildByDeptId 与 checkDeptExistUser 做前置校验，直接走物理删除；前端删除前也未发起子部门存在性校验请求 |
| 影响范围 | 部门表、用户表 dept_id 外键关联数据；若误删顶级部门，全公司层级用户数据权限同时失效 |
| 修复方案 | 删除接口追加两步前置校验 + 前端删除前调用 `/system/dept/hasChild/{deptId}` 预检，匹配后拦截并提示 |
| 当前状态 | 已关闭，回归通过 |

**典型缺陷 2：角色管理-分配权限菜单树未按父子层级联动选中（严重）**

| 项 | 内容 |
|---|---|
| 缺陷 ID | BUG-002 |
| 触发场景 | 分配权限时勾选父级菜单「系统管理」，子菜单不自动跟随选中；保存后后端权限集合缺失子项 |
| 根因分析 | 前端 Treeselect 组件 checkStrictly=true 配置关闭了父子联动，同时后端 saveMenuPerm 未对父-子权限集合做并集补全 |
| 影响范围 | 新配置的角色无法拿到完整菜单权限，需测试/运维人员手动逐一勾选子菜单，存在漏配风险 |
| 修复方案 | 调整 menuTreeselect 为半选联动模式，后端保存前基于选中的父节点递归补全子节点 ID |
| 当前状态 | 已解决，待回归验证 |

**典型缺陷 3：系统日志-操作日志跨月查询返回空数据（一般）**

| 项 | 内容 |
|---|---|
| 缺陷 ID | BUG-004 |
| 触发场景 | 操作日志筛选 2026-06-25 至 2026-07-26 的跨月区间 |
| 根因分析 | SysOperLogMapper.xml 中 `params.beginTime`/`endTime` 未补零时间部分（HH:mm:ss），直接 DATE() 转换导致跨月时 BETWEEN 边界缺失；同时请求参数未做 yyyy-MM-dd HH:mm:ss 标准格式化 |
| 影响范围 | 审计场景（月度合规检查、月度问题回溯）无法拉取完整日志数据 |
| 修复方案 | Mapper.xml 中统一使用 `DATE_FORMAT(oper_time, '%Y-%m-%d %H:%i:%s')` 范围比较，Controller 层 params 补齐 beginTime 00:00:00 / endTime 23:59:59 |
| 当前状态 | 新建，计划下一轮迭代修复 |

## 6. 风险与遗留问题

### 6.1 遗留缺陷清单（4 条新建状态）

| 缺陷 ID | 模块 | 标题 | 严重程度 | 风险评估 | 建议处理计划 |
|---|---|---|---|---|---|
| BUG-001 | 用户管理 | 新增用户手机号 12 位未拦截 | 一般 | 低：脏数据入库但不影响鉴权，可后续数据清洗 | 迭代 2 修复 |
| BUG-004 | 系统日志 | 操作日志跨月查询返回空 | 一般 | 中：月度审计场景受影响，日常按日/周查询不受限 | 迭代 2 修复，审计前发布热修复 |
| BUG-007 | 用户管理 | 状态切换后列表未实时刷新 | 一般 | 低：手动刷新可规避，不影响数据正确性 | 迭代 2 修复 |
| BUG-009 | 菜单管理 | 排序字段允许负数 | 轻微 | 低：仅 UI 顺序异常，管理员可通过正整数修正 | 迭代 2 修复或接受 |

### 6.2 风险项

1. **性能基线偏低风险**：基准采样中用户列表（1000 条 / 页）在 20 并发下 90 分位响应 980ms，高于通用后台 500ms 推荐线。当前上线数据量小不阻塞，建议在第二轮迭代引入分页查询 SQL 优化与 Redis 二级缓存。
2. **自动化覆盖不足风险**：仅完成登录、用户、角色主流程 3 条脚本骨架，日志与菜单模块尚未脚本化。第二轮迭代建议自动化用例占比达到 P0 用例的 80%。
3. **数据权限回归风险**：自定义数据权限（BUG-012）修复后仅覆盖「研发部门」单一场景；跨部门嵌套、同时兼任多角色等组合场景尚未全量回归，需在下一轮补充专项用例。
4. **日志跨月查询影响审计**：BUG-004 若不提前修复，月度审计节点需运维侧直接查询数据库导出，存在人工操作成本。

### 6.3 暂不处理项

- 菜单图标（BUG-005）、登录日志类型（BUG-011）虽已修复关闭，但部分第三方图标字体在低版本浏览器加载偶发空白，非本项目主流程问题，接受为已知限制。
