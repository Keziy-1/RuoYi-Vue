## 一、项目背景

本项目基于开源前后端分离管理系统框架 RuoYi-Vue 开展全流程软件测试实践，模拟企业真实项目测试流程，独立完成从测试策划、用例设计、测试执行到缺陷管理、报告输出的完整闭环。

项目覆盖功能测试、接口测试、基础性能测试、接口自动化回归四大专项，旨在验证系统核心功能的正确性、稳定性与基础性能表现，同时沉淀标准化测试资产，形成可复用的企业级测试项目经验。

## 二、测试目标

1. 验证系统核心业务模块的功能正确性，确保主流程与关键异常场景符合预期
2. 验证后端接口的可用性、鉴权机制与业务场景串联能力
3. 评估核心接口在基础并发场景下的性能表现，输出性能基准数据
4. 搭建接口自动化回归脚本，支撑后续版本迭代的快速验证
5. 建立完整的缺陷生命周期管理流程，沉淀标准化测试文档与项目资产

## 三、测试范围

### 3.1 核心测试模块

| 模块名称 | 测试内容 | 优先级 |
|----------|----------|--------|
| 系统认证 | 登录、登出、Token鉴权、验证码、权限菜单加载 | P0 |
| 用户管理 | 用户新增、编辑、删除、查询、禁用/启用、密码重置、导入导出 | P0 |
| 角色管理 | 角色新增、编辑、删除、权限分配、数据权限配置 | P1 |
| 菜单管理 | 菜单新增、编辑、删除、菜单排序、按钮权限配置 | P1 |
| 部门管理 | 部门新增、编辑、删除、树形结构展示与查询 | P1 |
| 系统日志 | 操作日志查询、登录日志查询、日志删除与导出 | P2 |

### 3.2 测试类型

- **功能测试**：覆盖核心模块的正向流程、异常校验、边界值、权限控制
- **接口测试**：单接口参数校验、鉴权机制验证、业务场景串联、接口关联提取
- **性能测试**：核心接口基础并发压测，验证系统吞吐量与响应时间
- **自动化测试**：基于 Python + pytest + requests 实现核心业务流接口自动化回归

### 3.3 不测试范围

- 代码生成器、在线构建器等开发工具类模块
- 定时任务、服务监控、服务监控等运维类模块
- 多数据源、分布式部署等企业级扩展功能
- 移动端适配与多浏览器深度兼容性测试

## 六、进度规划

**总周期：10个工作日**

| 阶段 | 耗时 | 工作内容 | 交付物 |
|------|------|----------|--------|
| 测试策划 | 1天 | 需求分析、测试计划编写、测试点拆解 | 测试计划文档、功能测试点分析 |
| 用例设计 | 1天 | 测试用例编写、评审、导入禅道 | 系统测试用例 |
| 功能测试 | 2天 | 功能测试执行、缺陷提交与跟踪验证 | 缺陷记录台账、功能测试执行记录 |
| 接口测试 | 2天 | 接口梳理、单接口测试、场景串联、鉴权处理 | Postman接口集合、接口测试结果 |
| 性能测试 | 1天 | 压测脚本开发、并发压测执行、结果分析 | JMeter脚本、性能测试小结 |
| 自动化测试 | 2天 | 自动化框架搭建、核心用例脚本开发、执行调优 | pytest自动化脚本、自动化报告 |
| 总结归档 | 1天 | 测试报告编写、资产整理、GitHub归档 | 迭代测试报告、完整项目资产 |

## 七、测试准入与准出标准

### 7.1 准入标准
1. 开发环境部署完成，系统可正常启动访问
2. 核心业务模块开发完成，冒烟测试通过
3. 测试计划与测试用例评审通过
4. 测试环境数据准备完毕

### 7.2 准出标准
1. 测试用例执行率达到 100%
2. P0、P1级缺陷全部修复并验证通过
3. 遗留缺陷均为P2级及以下，且不影响主流程使用
4. 接口测试通过率 ≥ 95%
5. 核心接口性能满足预期指标
6. 测试报告与所有资产归档完成

## 八、缺陷管理规范

### 8.1 缺陷严重等级定义

| 严重等级 | 定义 | 示例 |
|----------|------|------|
| 致命 | 系统崩溃、数据丢失、核心功能完全不可用 | 登录接口500报错、数据库连接异常导致系统无法使用 |
| 严重 | 核心功能失效、主要业务流程无法走通 | 新增用户提交无响应、用户删除后数据仍存在 |
| 一般 | 次要功能异常、不影响主流程使用 | 查询条件组合异常、分页跳转偶发失效 |
| 轻微 | UI展示问题、文案错误、交互细节优化 | 按钮文字错位、提示文案不规范 |

### 8.2 缺陷优先级定义
- **高**：必须立即修复，影响当前测试进度
- **中**：正常迭代修复，版本发布前必须解决
- **低**：可延后处理，不影响核心功能使用

### 8.3 缺陷生命周期
新建 → 指派 → 已确认 → 已解决 → 验证通过 → 已关闭  
验证不通过 → 重新打开 → 重新指派

## 九、风险与应对措施

| 风险项 | 影响 | 应对措施 |
|--------|------|----------|
| 测试环境崩溃 | 测试进度阻塞 | 提前备份数据库与配置文件，制定环境快速恢复方案 |
| 接口鉴权异常 | 接口测试无法进行 | 优先排查Token有效性、请求头格式、接口路径正确性 |
| 压测结果异常 | 性能测试结论失真 | 逐步降低并发数，排查脚本问题与环境瓶颈，多轮取均值 |
| 自动化脚本不稳定 | 回归结果不可靠 | 封装公共请求方法、增加异常捕获、优化断言逻辑 |
| 功能理解偏差 | 用例设计遗漏 | 参考官方文档与系统实际表现，交叉验证业务逻辑 |
