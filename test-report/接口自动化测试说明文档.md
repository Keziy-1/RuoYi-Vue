## 1. 项目简介

### 1.1 项目定位

本项目是为 RuoYi-Vue v3.9.2 后台管理系统定制的 **轻量级接口自动化回归测试框架**，定位于 **核心业务流回归自动化**，目标是在每轮功能迭代发版前快速验证系统管理模块（认证、用户、角色、菜单、部门）的核心接口能力，替代人工重复执行 P0/P1 级接口用例，**显著提升迭代验证效率，缩短回归周期，降低人工遗漏风险**。

### 1.2 设计原则

- **轻量可落地**：不引入 pytest-xdist、allure、ddt 等重组件，仅依赖 requests + pytest + pytest-html，零学习成本，新成员 10 分钟可上手运行。
- **与项目业务完全对齐**：接口路径、鉴权方式、参数结构严格贴合 RuoYi-Vue v3.9.2 真实实现，不封装抽象过度导致与实际业务脱节。
- **一次编写多环境复用**：base_url、账号、开关项全部抽离到配置层，同一套脚本可在本地开发、测试、预发布环境复用。
- **失败可追溯**：每条用例失败自动打印请求 URL / Method / Headers / Body / 响应体，附带断言信息，配合 pytest-html 报告直接定位问题。

### 1.3 覆盖范围

| 范围层 | 说明 |
|---|---|
| ✅ 已覆盖模块 | 认证模块、用户管理模块、角色管理模块、核心业务流串联 |
| 🔜 规划中（按迭代补充） | 菜单管理、部门管理、系统日志、字典/参数等 |
| ❌ 不覆盖 | 前端 UI 交互、性能压测、上传下载字节级正确性、图片验证码识别（测试环境关闭验证码） |

## 3. 框架目录结构

```text
ry_api_auto/
├── common/                          # 公共层（工具、封装、fixture）
│   ├── __init__.py
│   ├── request_client.py            # 统一 HTTP 客户端：封装 requests.Session，自动注入 Token、记录日志、异常兜底
│   ├── auth_client.py               # 鉴权封装：自动获取/刷新 JWT Token，401 时自动登录重试 1 次
│   ├── assertions.py                # 统一断言工具：业务 code=200、分页 rows/total 一致性、字段存在性
│   ├── data_builder.py              # 数据构造：userName/phonenumber 等唯一字段 UUID 生成、随机部门/角色取数
│   ├── db_helper.py                 # 数据库校验（可选）：MySQL 查询 sys_user / sys_role 等表验证写入正确性
│   └── logger.py                    # 日志：控制台 + 本地日志文件，请求/响应自动打日志
│
├── testcases/                       # 用例层（按模块 + 业务流分目录，文件名 test_*.py）
│   ├── __init__.py
│   ├── conftest.py                  # 全局 fixture：环境初始化、Token 获取、数据清理钩子
│   ├── test_auth/                   # 认证模块用例
│   │   ├── test_login.py            # 登录正常/账号密码错/验证码错/无验证码参数
│   │   ├── test_logout.py           # 登出后 Token 失效
│   │   ├── test_getinfo_getrouters.py # 获取用户信息/菜单路由权限校验
│   │   └── test_update_password.py  # 修改自身密码（新老密码/旧密码错误）
│   ├── test_user/                   # 用户管理模块用例
│   │   ├── test_user_list.py        # 列表分页/多条件筛选/deptId 过滤/status 筛选
│   │   ├── test_user_crud.py        # 新增/修改/删除/详情查询
│   │   ├── test_user_status.py      # 启用/停用切换、停用后登录失败
│   │   └── test_user_reset_pwd.py   # 管理员重置密码、重置后旧密码失效
│   ├── test_role/                   # 角色管理模块用例
│   │   ├── test_role_list.py        # 列表分页/角色名/状态筛选
│   │   ├── test_role_crud.py        # 新增/修改/删除、角色名重复校验
│   │   ├── test_role_menu_scope.py  # 分配菜单权限（sys_role_menu 写入一致）
│   │   └── test_role_data_scope.py  # 分配数据权限（sys_role_dept 写入一致）
│   └── test_workflow/               # 完整业务流串联用例
│       ├── test_org_init_workflow.py  # admin 登录→建部门→建角色配权限→建用户配角色
│       └── test_newuser_perm_workflow.py # 新用户登录→验证菜单/数据权限→越权写操作被拦截
│
├── testdata/                        # 数据层（YAML/JSON，可修改不改动代码）
│   ├── accounts.yaml                # 多环境账号：admin/普通角色/只读用户等
│   ├── user_testdata.yaml           # 新增/修改用户的请求体模板、边界值数据集
│   ├── role_testdata.yaml           # 新增/修改角色请求体模板、数据权限枚举数据集
│   └── workflow_testdata.yaml       # 业务流串联场景参数（部门名/角色名/用户名前缀）
│
├── config/                          # 配置层
│   ├── settings.py                  # 全局常量：超时、重试次数、数据清理开关
│   ├── env_dev.yaml                 # 本地开发环境：base_url、redis、db 连接等
│   ├── env_test.yaml                # 测试环境配置（与 dev 同结构，base_url 切换）
│   └── pytest.ini                   # pytest 默认参数：-v -s --html=reports/report.html 等
│
├── reports/                         # 报告层（每次运行自动生成，.gitignore 忽略）
│   ├── report_<日期>_<时间戳>.html  # pytest-html 输出（含用例、错误详情、环境信息）
│   └── logs/                        # 每日请求日志：<YYYY-MM-DD>.log

├── requirements.txt                 # 依赖清单

## 4. 用例覆盖范围

### 4.1 认证模块（test_auth/）

| 用例文件名 | 覆盖的核心场景 | 优先级 |
|---|---|---|
| `test_login.py` | admin 正确账号密码登录成功返回 token / 用户名错返回提示「用户不存在/密码错误」 / 密码错 1 次计数+ / 验证码错提示「验证码错误」 / 缺少 code/uuid 参数登录失败 | P0 |
| `test_logout.py` | 登录后调用 `/logout` 成功；登出后使用原 token 请求列表接口返回 401 | P0 |
| `test_getinfo_getrouters.py` | admin 登录 getInfo 返回 `permissions=["*:*:*"]` / admin getRouters 返回全量菜单树 / 普通只读角色 getInfo permissions 仅含查询项 / getRouters 树结构与角色分配一致 | P0 |
| `test_update_password.py` | 修改自身密码（旧密码正确→成功）/ 旧密码错误→提示「修改密码失败，旧密码错误」 / 新密码两次不一致→前端校验（接口层不校验直接失败） | P1 |

### 4.2 用户管理模块（test_user/）

| 用例文件名 | 覆盖的核心场景 | 优先级 |
|---|---|---|
| `test_user_list.py` | 默认分页（pageSize=10）/ pageNum=2 翻页 / userName 模糊查询 / phonenumber 精确查询 / status=0 启用过滤 / deptId=103 部门过滤 / pageSize=100 大分页 / pageNum=0 边界 | P0 |
| `test_user_crud.py` | 新增用户（必填全字段）→ 详情查询字段对齐一致 / 修改用户 nickname/email/phonenumber → 详情查询回读一致 / 删除单个存在 userId → 列表不存在该记录 / 批量删除多个 userId → 均被删除 / 新增已存在 userName → 提示「新增用户'xxx'失败，账号已存在」 / 修改不存在 userId → code=500 友好提示 / 删除不存在 userId → 不报错影响行数 0 | P0 |
| `test_user_status.py` | admin 把正常用户 status=0 → 1 停用 → 用该用户登录返回账号停用 401 / 再改回 0 启用 → 登录恢复成功 / 已停用用户再次停用 → 容错成功 | P1 |
| `test_user_reset_pwd.py` | admin 重置用户密码为新值 → 新密码可登录 / 重置后用户原密码登录→失败 / 重置不存在 userId → 接口提示 | P1 |

| 用例文件名 | 覆盖的核心场景 | 优先级 |
|---|---|---|
| `test_role_list.py` | 默认分页列表 / roleName=管理员 模糊查询 / roleKey=admin 精确查询 / status=0 启用过滤 / 组合条件多筛 | P0 |
| `test_role_crud.py` | 新增角色（必填全字段 + menuIds 数组）→ 详情读取一致 / 修改角色 remark/status → 回读一致 / 删除存在且未被用户引用的 roleId → 删除成功且 sys_role_menu 中间表同步删 / 删除已被用户引用 roleId → 拦截失败「角色已分配，不能删除」 / 新增已存在 roleName → 提示「角色名称已存在」 | P0 |
| `test_role_menu_scope.py` | 给角色分配部分菜单 menuIds=[1,2,100,101] → 立即登录该角色 getRouters → 仅返回分配到的菜单 / 再次修改 menuIds=[] → getRouters 返回空 | P1 |

## 5. 环境部署与运行步骤

### 5.1 前置准备

| 序号 | 检查项 | 说明 |
|---|---|---|
| 1 | Python 版本 | 本机已安装 Python 3.9.x，`python -V` / `py -V` 能正常显示版本 |
| 2 | RuoYi-Vue 后端可用 | 本地后端服务已启动在 `http://localhost:8080`，接口可访问 |
| 3 | 验证码关闭（测试环境） | 测试环境建议在 `sys_config` 中将 `sys.account.captchaEnabled` 设置为 `false`；若开启，需在 `auth_client.py` 中对接 OCR 或自行扩展验证码获取方案 |

  username: "ry"

```

### 5.5 步骤 4：执行用例

**方式 A：一键入口（推荐新手）**
```bash
python run.py
# run.py 内部等价于：pytest -v -s --html=reports/report_latest.html --self-contained-html
```

**方式 B：pytest 命令行灵活控制**
```bash
# 1. 跑全部用例 + 生成 HTML 报告
pytest -v -s --html=reports/report_%date:~0,4%%date:~5,2%%date:~8,2%.html --self-contained-html

# 2. 只跑认证模块
pytest testcases/test_auth/ -v -s

# 3. 只跑用户管理的 P0 用例（通过 pytest.mark.p0 标记过滤）
pytest testcases/test_user/ -v -s -m p0

# 4. 只跑业务流串联 + 失败自动重跑 1 次
pytest testcases/test_workflow/ -v -s --reruns 1

# 5. 并行跑（如未来装了 pytest-xdist，当前版本不包含）
# pytest -v -s -n 3
```

### 5.6 步骤 5：查看报告与日志

- **HTML 报告**：打开 `reports/report_<日期>.html`，顶部显示环境（base_url、Python、pytest 版本）、执行摘要（总数/通过/失败/跳过/错误）、失败用例展开可直接看 Request URL / Headers / Body / Response / 断言错误堆栈。
- **请求日志**：`reports/logs/<YYYY-MM-DD>.log`，每条请求均记录 `[时间][模块][方法][URL][状态码][耗时ms]`，失败时追加响应体便于离线复盘。

### 5.7 常见问题排错

| 现象 | 排查顺序 |
|---|---|
| 全部用例报 `ConnectionError` / `Max retries exceeded` | ① 浏览器直接访问 `http://localhost:8080/captchaImage` 是否能返回 JSON → ② 确认后端未启动/端口不一致 → ③ 修改 `env_dev.yaml` base_url |
| 登录失败提示「验证码错误」或「验证码已失效」 | ① 测试环境建议关闭验证码 → ② sys_config 中 `sys.account.captchaEnabled` 是否 true → ③ 若保持开启，需在 `auth_client.login()` 中先请求 `/captchaImage` 获取 uuid 再提交 |
| list / add 等接口 401 | ① 检查 `reports/logs/` 中 token 是否真的带上了 Authorization → ② Token 超 30 分钟过期 → 本框架 `auth_client` 对 401 自动重试登录 1 次，重试仍失败才断言失败 |
| 新增用户提示「用户名已存在」 | 本框架 `data_builder.py` 已使用时间戳 + UUID 保证唯一性，若仍重复 → 检查 `auto_cleanup=false` 未清理上次遗留数据 |

## 6. 扩展规划

### 6.1 短期（1~2 个迭代内）：持续补充用例

| 优先级 | 扩展项 | 落地方式 |
|---|---|---|
| P0 | 菜单管理 / 部门管理模块补全 | 新增 `testcases/test_menu/`、`testcases/test_dept/` 目录，按 §4 风格分别覆盖列表/CRUD/父子联动删除/树形接口，预计新增 18~22 条用例 |
| P1 | 数据驱动升级（边界值/异常值批量） | 用户管理的 `phonenumber` 10~12 位、email 合法/非法、`orderNum` 负数/0/超大值等，使用 `@pytest.mark.parametrize` 读取 `testdata/user_testdata.yaml` 数据集批量生成用例，减少重复断言代码 |
| P1 | 数据清理钩子强化 | 在 `conftest.py` 中增加 session 级别的 fixture：记录所有以 `auto_`/`itest_` 前缀新增的 deptId/roleId/userId/menuId，全部用例结束后统一反序删除（用户→角色→部门→菜单），避免脏数据累积 |

### 6.2 中期：接入 CI / 定时回归

| 扩展项 | 落地步骤 |
|---|---|
| **接入 Jenkins / GitLab CI** | ① 本项目提交到 Git 仓库 → ② Jenkins 新建 Pipeline：拉代码 → 装 venv + 依赖 → 执行 `pytest ...` → 归档 `reports/*.html` + 日志 → ③ Build 触发条件：**每次后端 MR** 跑 P0、**每日 22:00** 跑全量 → ④ 失败自动邮件通知测试/开发负责人 |
| **失败用例自动提单（对接禅道）** | 在 `common/zentao_client.py` 中实现：用例失败后调用禅道开放接口，自动创建「接口自动化-失败」Bug，附带报告 URL、请求/响应报文、环境信息，减少人工录入 |
| **多环境切换** | Jenkins 参数化构建传入 `ENV=dev/test/pre`，`conftest.py` 读取后对应加载 `env_dev.yaml / env_test.yaml / env_pre.yaml`，一套脚本多环境复用 |

### 6.3 长期：架构升级（按需）

- **报告升级**：pytest-html → Allure2，支持用例分类/趋势图/历史对比/负责人标注；
- **性能接口自动化**：在同一框架层引入 locust 或复用 requests 扩展简单基线 QPS 采样；
- **契约测试引入**：新增/修改接口时，先运行 OpenAPI Swagger 契约校验脚本，确保 Knife4j 文档定义与实际返回字段严格一致，**提前阻断接口契约变更引入的下游故障**。
